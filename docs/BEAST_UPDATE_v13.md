# AGNES-BRAIN TINY LLM ARCHITECTURE NOTES
## Inspired by esp32-tinyllm (28.9M params on $8 ESP32-S3)

The esp32-tinyllm project proves that extremely small models can be powerful
specialists. It runs a 28.9M parameter Gemma-style transformer on a microcontroller
using per-layer embeddings to keep 25M params in flash memory.

Agnes-Brain scales this idea up to 1B parameters and specialises for GP tasks.

## Why 1B and not 28.9M?

28.9M parameters is sufficient for storytelling on fixed vocabulary (the ESP32 use case).
GP primitive suggestion requires: understanding JSON schema, understanding type systems,
understanding what "pure function" means, and avoiding contamination.
1B parameters reliably learns these constraints. 28.9M does not.

## Why not 7B, 13B, or 70B?

7B+ requires 8+ GB RAM — not available on most developer machines.
Agnes-Brain must run on the same machine as the evolution engine.
The evolution engine uses 35-100 MB for population 500.
Agnes-Brain at 1B + 4-bit quantisation uses 800 MB.
Total: ~1 GB, fits on any machine with 2 GB RAM.

## The Three-Job Rule

Agnes-Brain has exactly three jobs:
1. Suggest primitives — help design the search space for new tasks.
2. Generate test cases — help create fitness evaluators from examples.
3. Explain champions — make evolved code understandable to humans.

She has NO other jobs. No chat. No code generation. No web browsing.
This constraint is what makes her accurate — she is the world's best expert
at exactly three things related to genetic programming.

## Why locally trained?

A general LLM (Claude, GPT-4) trained on the internet knows what "sort" means
from millions of examples. Agnes-Brain trained on our data knows what "sort1"
means in the context of OUR primitive registry, OUR contamination rules, and
OUR fitness evaluators. That specificity is the advantage.

## Training data scale

500 training examples is enough for LoRA fine-tuning of a 1B parameter base model.
LoRA updates only 0.1-1% of parameters (the adapter layers). The base model's
general capabilities (JSON output, Python understanding, type awareness) are
preserved. Only the task-specific behaviour is tuned.

## If fine-tuning fails

If fine-tuning is not available (no GPU, no time), the base model (qwen2.5:1.5b
or llama3.2:1b) with our specific prompts still gives approximately 60-70%
valid JSON output. Our client handles failures gracefully (returns None on
invalid JSON). Evolution still works without Agnes-Brain — she is an enhancement
not a requirement. If Agnes-Brain is unavailable, the system falls back to
default primitive sets and no test case generation assistance.
