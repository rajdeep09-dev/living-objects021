# BEAST v8 Discovery-Log Protocol

## Admission rule

A record may enter the discovery log only after all pre-registered seeds finish, the aggregate threshold is met, every terminal fresh suite passes its declared threshold, the final tree is absent at generation zero, and the profile’s contamination status permits the stated claim. Failed and retracted experiments remain in the benchmark ledger and are not discarded.

| Field | Purpose |
|---|---|
| `record_id` and pre-registration ID | Bind an entry to one declared protocol. |
| Task, seed, generation | Identify the exact terminal candidate. |
| Tree hash and primitive list | Permit structural review without executing exported source. |
| Node count and first perfect generation | Preserve complexity and discovery timing. |
| Fresh suite payload | Preserve evaluator-owned independent evidence. |
| Generation-zero containment check | Prevent a starting individual from being reported as discovered. |
| Trial artifact path | Make the full history, lineage, checkpoint, and source audit export inspectable. |

The machine-readable [`v8-discovery-log.json`](v8-discovery-log.json) is generated by `python3 scripts/build_v8_evidence_ledger.py`; it is not hand-authored. In this release it contains only the five eligible Manhattan-distance records and labels them as bounded evaluator-specific compositional solutions.
