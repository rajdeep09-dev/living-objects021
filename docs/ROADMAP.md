## Phase 3: Schema-Driven Generation (Months 4-6)

**Goal:** Prove that a schema can generate a persistent intelligent object.

**Prototype:**
1. Define schema vocabulary (10 primitives)
2. Build Object Factory (schema → executable object)
3. Create 3 object types from schemas (Customer, Product, Order)
4. Test: create → interact → terminate → restart → verify
5. Measure: developer time, lines of code, functionality

**Decision Gate:**
- Schema expressiveness >50%?
- Developer time reduced >30%?
- Objects survive restart?
- Functionally equivalent?

**If gate fails:** Pivot to "enhanced NOOA with persistence"

---

## Phase 4: Object Graph (Months 7-9)

**Goal:** Prove that intelligent object graphs self-coordinate.

**Prototype:**
1. Company → Customer, Product, Order, Inventory graph
2. Each object generated from schema
3. Objects communicate via capability-based relationships
4. Compare: explicit orchestration vs. object self-coordination

**Decision Gate:**
- Self-coordination requires <50% of orchestration code?

---

## Phase 5: Experimentation & Learning (Months 10-12)

**Goal:** Prove that structured experience memory improves behavior.

**Prototype:**
1. Object has a decision task
2. Records experiences: observation → action → result → lesson
3. Uses experience memory for future decisions
4. Compare: no memory, raw history, structured experience

**Decision Gate:**
- >20% improvement over no memory?
- <50% tokens of raw history?

---

## Phase 6: Controlled Evolution (Months 13-15)

**Goal:** Prove that objects can improve strategies without destabilizing.

**Prototype:**
1. Object proposes policy improvements
2. Runtime tests in sandbox
3. If improved: adopt with versioning
4. If worse: rollback

**Decision Gate:**
- >30% of experiments succeed?
- <5% regression rate?

---

## Phase 7: Scale Test (Months 16-18)

**Goal:** Prove the Sparse Cognition Hypothesis.

**Prototype:**
1. Simulate 1 → 10 → 100 → 1,000 → 10,000 objects
2. Measure actual active fraction α
3. Test: event-driven vs. polling, importance filtering

**Decision Gate:**
- α < 0.01 for 90% of scenarios?
- Cost scales sub-linearly?

---

## Phase 8: Benchmarks & Comparisons (Months 19-21)

**Goal:** Prove the paradigm is genuinely better for specific use cases.

**Benchmarks:**
1. Living Website (anomaly detection + adaptation)
2. Object Graph (Company → Customer → Product)
3. Memory Comparison (6 memory strategies)
4. Evolution Benchmark (controlled improvement)
5. Scale Benchmark (10,000 objects)
6. Security Benchmark (red team)
7. Developer Experience (time, code, bugs)

---

## Phase 9: Formalization & Decision (Months 22-24)

**Goal:** Determine what the result actually is.

**Options:**
- Framework
- Runtime
- Programming model
- Protocol
- Programming language
- Object database
- Developer platform
- Research paper
- Startup
- Something else entirely

**Decision:** Follow the evidence.

---

## North Star

> What becomes possible when software objects can think?

The two-year objective is not to prove the original thesis correct. It is to discover whether intelligent persistent software objects represent a genuinely useful next step in software architecture.
